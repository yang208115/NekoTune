# NekoTune

NekoTune 是一款本地优先的 Linux 音乐播放器，使用 C++20、Qt6 和 QML。曲库、歌单、队列、歌词和配置由本机管理；酷狗搜索与下载、在线歌词和 AI 歌曲信息填写按需使用网络服务。

桌面程序 `nekotune` 在一个进程内运行界面和后端。项目同时提供独立后端与独立前端，三种程序共用同一套本地 Socket API。

## 功能

| 功能 | 当前行为 |
| --- | --- |
| 首页 | 显示当前播放、最近加入的歌曲和歌单入口 |
| 本地曲库 | 导入音频、自动扫描、搜索、批量选择、编辑歌曲信息和多标签筛选 |
| 歌单 | 创建、重命名、导入、添加歌曲及按当前浏览顺序播放 |
| 播放队列 | 独立抽屉，支持追加、移除、清空和重启恢复 |
| 播放控制 | 播放／暂停、停止、上一首、下一首、跳转、音量；顺序、单曲循环、随机和列表循环 |
| 歌词与封面 | 本地优先，支持 LRC、KRC 词组高亮、在线候选选择和离线缓存 |
| 酷狗音乐 | 匿名搜索、短信登录、下载音频及配套歌词和封面 |
| AI 歌曲信息 | 通过兼容 Chat Completions 的服务生成歌名、歌手和标签建议，确认后保存 |
| 语言 | 中文／英文，可在设置中切换 |

文件选择和扫描支持 `mp3`、`m4a`、`aac`、`wav`、`flac`、`ogg`；实际解码能力取决于本机 Qt Multimedia 后端及音频编解码库。

## 构建与启动

### 依赖

- CMake 3.28+、支持 C++20 的编译器和 `pkg-config`。
- Qt 6.6+：Core、Gui、Network、Sql、Multimedia、Quick、Qml、QuickControls2、Test、QuickTest。
- Zlib 和 FFmpeg 开发库：`libavformat`、`libavutil`。
- QtKeychain 0.17+ 的 Qt6 开发包，CMake 包名为 `Qt6Keychain`。
- Linux 还需 `libsecret-1` 开发库，用于读取并迁移旧版系统密钥库条目。

仓库面向 Linux 桌面使用。凭据适配器包含 Windows/macOS 支持，完整应用在这些平台的构建和运行仍需对应平台验收。

在仓库根目录执行：

```sh
cmake -S . -B build
cmake --build build --parallel
./build/nekotune
```

启动后默认打开「首页」。QML、图片与翻译文件嵌入可执行文件，Qt、QtKeychain 和其他动态库仍需安装；当前构建产物不是包含所有运行依赖的分发包。

### 分离运行

在两个终端中分别启动后端与前端：

```sh
# 终端 1
./build/backend/nekotune-backend
```

```sh
# 终端 2
./build/frontend/qt-qml/nekotune-qt-qml
```

两者默认连接名为 `nekotune`，可用 `NEKOTUNE_SOCKET` 覆盖。Linux 使用 Unix domain socket；统一桌面程序也保留此接口。相同连接名同时只能运行一个后端。

### 隔离开发数据

```sh
nekotune_profile=$(mktemp -d /tmp/nekotune-dev.XXXXXX)
NEKOTUNE_HOME="$nekotune_profile" \
NEKOTUNE_SOCKET="$nekotune_profile/nekotune.sock" \
./build/nekotune
```

此目录会保留此次运行的数据。分离运行时，两个终端必须使用相同的 `NEKOTUNE_HOME` 和 `NEKOTUNE_SOCKET`；仅改变 Socket 不会隔离曲库。

## 使用

### 浏览与播放

单击歌曲行选中，双击或按 Enter 播放；行首播放按钮可直接播放／暂停。曲库支持 Ctrl 增减选择、Shift 区间选择。搜索或标签条件变化会清除选择；选择多个标签时，结果必须同时拥有所有所选标签。

曲库和歌单的播放操作按当前可见列表生成队列。首页「最近加入」按其展示列表播放。曲库播放会跳过不可用文件并提示数量；没有可播放歌曲时保留当前队列。切换页面、搜索和选择本身不会改变播放状态。

| 导入入口 | 结果 |
| --- | --- |
| 首页／曲库「导入音乐」 | 加入曲库 |
| 歌单「导入音乐」 | 加入曲库和该歌单 |
| 队列抽屉「添加音乐」 | 加入曲库并追加队列 |
| 酷狗下载 | 完成后加入曲库 |

以上操作均不自动切歌。队列保存顺序、重复项和当前项；清空队列不会删除曲库或歌单。删除歌单不会删除歌曲文件，也不影响其他歌单或当前队列。

底部播放栏始终可达。点击封面、歌名或歌词按钮进入正在播放页；返回后恢复原浏览页面。队列按钮展开右侧抽屉，停止播放位于底栏歌曲的更多菜单。

| 快捷键 | 操作 |
| --- | --- |
| Space | 播放／暂停；文字编辑或弹窗活动时禁用 |
| Ctrl+F | 聚焦当前页面提供的搜索框；队列抽屉展开时优先搜索队列 |
| Ctrl+O | 向当前浏览目标导入；队列抽屉展开时追加队列 |
| Esc | 关闭弹窗，或收起队列／退出正在播放页 |

### 歌词与封面

自动加载顺序为：同目录同名 `.krc` → `.lrc` → 自定义歌词 → 歌词缓存 → LRCLIB。损坏的 KRC 会尝试回退 LRC；「刷新」跳过自定义歌词和缓存，仍优先读取本地文件。自动在线结果只有满足可靠匹配条件才应用，其余候选由用户选择。

手动搜索可选 LRCLIB 或酷狗音乐。酷狗先选择歌曲版本，再选择歌词，优先获取 KRC，失败时回退 LRC；歌词搜索无需登录。成功获取的配套歌词和酷狗封面保存到歌曲的编号目录，扫描不会批量获取在线资源。

曲库、歌单、队列和播放器使用后端统一解析的封面：本地同名 `.jpg`、`.jpeg`、`.png`、`.webp` 优先，其次使用已选歌词或缓存中的封面地址。「仅本地歌词」模式使用本地歌词、缓存和本地封面，停止歌词网络请求及远程封面加载。

歌词诊断页可通过以下方式启用：

```sh
./build/nekotune --lyrics-debug
```

侧边栏会显示「歌词调试」，可查看时间戳、当前进度并点击歌词行跳转。旧版 ASR 数据保留，但当前程序不再读取或生成 ASR 歌词。

### 酷狗搜索与下载

酷狗音乐默认关闭，未预设 Worker 地址。在「设置 → 酷狗音乐」填写自己的 Worker 地址、勾选「启用酷狗音乐」并保存后，侧边栏显示酷狗入口，歌词搜索可选择酷狗来源。关闭后不再接受酷狗网络请求，保留已有密钥和登录资料。配置保存后立即生效并在重启后保留。

启用后「酷狗音乐」可匿名搜索，账号操作位于右上角弹窗。发送验证码、登录和下载需要在设置页保存与服务端 `ACCOUNT_API_KEY` 相同的密钥；密钥保存在系统密钥库，界面只显示配置状态。

也可使用 `KUGOU_ACCOUNT_API_KEY` 或 `KUGOU_ACCOUNT_API_KEY_FILE`。设置页保存的密钥优先，清除后回退到启动环境配置：

```sh
KUGOU_ACCOUNT_API_KEY_FILE=/path/to/private-account-key ./build/nekotune
```

密钥文件应仅自己可读。登录会话同样保存在系统密钥库，不读取其他项目的 Cookie。Worker 地址仅从设置页配置，远程地址要求 HTTPS，仅本机回环地址允许 HTTP；地址不能包含路径、账号信息、查询参数或片段。

下载使用服务端返回的临时 HTTPS 地址和固定 `128` 音质。可靠匹配时保存 KRC、LRC 和封面，已有下载文件不覆盖；配套资源失败不阻止音频入库。账号、歌曲或设备限制可能导致下载失败，具体原因由界面提示。当前没有 VIP 领取或升级操作。

### AI 歌曲信息

在「设置 → AI 歌曲信息」填写 API Base URL、模型 ID 和可选 API Key，保存后可测试连接；测试会调用一次模型。请求使用非流式 Chat Completions，并保留地址中的路径前缀。

在「编辑歌曲信息」中点击「AI 填写」。模型接收原始文件名、当前草稿、标签和本地歌词文字，不上传音频、歌曲 hash 或绝对路径，不进行在线资料检索。建议只进入编辑框；检查后点击「保存」才写入曲库，不修改音频内嵌标签。

地址和模型保存在设置文件中，Key 按配置目录和服务地址保存在系统密钥库。Key 输入留空保留当前服务的 Key，切换服务不会沿用其他服务的 Key。请求总超时为 60 秒，关闭编辑器会丢弃迟到结果；生成期间仍可控制播放。

## 数据与删除

默认目录如下：

```text
~/Music/NekoTune/
├── 000001/
│   ├── 000001.flac       # 下载的音频，或指向外部音频的软链接
│   ├── 000001.krc        # 可选配套歌词
│   ├── 000001.lrc
│   └── 000001.jpg        # 可选封面，也支持其他图片格式
└── config/
    ├── nekotune.sqlite3  # 歌曲、路径、歌单、标签、队列和资源登记
    ├── settings.json     # 语言、播放模式、歌词离线设置、AI 配置等
    ├── lyrics-cache/
    └── covers/
```

歌曲按音频 SHA-256 去重，新资源使用至少六位的递增编号。外部导入只对原音频建立绝对软链接，程序获取的歌词和封面是托管目录中的真实文件；已有下载文件不会自动搬移或改名。音频断链后保留资料及配套文件，并显示不可用。

后端启动和前端连接会请求扫描，已有扫描进行时不重复启动。扫描更新曲库和缺失时长，跳过 `config`、目录软链接和已记录删除的歌曲，不修改队列或自动播放。手动重新导入或下载可以恢复已删除歌曲。

曲库删除会同时移除歌曲、歌单关联和队列项。界面确认框默认勾选「同时清理 NekoTune 托管的歌曲文件」：删除登记的托管音频及同名歌词、封面；外部导入仅删除软链接，保留外部原音频和其他文件。取消勾选后只删除记录。API 的 `library.delete` 默认不清理文件，需明确传入 `clean_files: true`；详细事务和清理失败行为见 [API 文档](docs/API.md)。

首次使用默认目录会迁移旧数据库、配置和缓存，保留旧数据库及已有目标数据；旧明文凭据只有在系统密钥库写入并回读校验成功后才删除。配置目录权限为 `0700`。密钥库不可用或拒绝访问时会报错，不回退明文存储。

| 环境变量 | 用途 |
| --- | --- |
| `NEKOTUNE_HOME` | 覆盖音乐根目录；显式设置时不迁入原用户配置 |
| `NEKOTUNE_DB_PATH` | 单独覆盖 SQLite 路径，不改变音乐和缓存目录 |
| `NEKOTUNE_SOCKET` | 覆盖本地 Socket 名称或路径 |
| `NEKOTUNE_LANGUAGE` | 指定 `zh`／`en`，优先于保存的设置和系统语言 |
| `KUGOU_ACCOUNT_API_KEY` | 设置酷狗服务密钥 |
| `KUGOU_ACCOUNT_API_KEY_FILE` | 从私有文件读取酷狗服务密钥 |

## 开发与验证

```sh
QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software \
ctest --test-dir build --output-on-failure
git diff --check
```

Linux 密钥库相关集成测试通过 `dbus-run-session` 和 `gnome-keyring-daemon` 创建临时密钥环；缺少这些运行工具时，相应测试标记为跳过。Windows/macOS 可用 `-DNEKOTUNE_TEST_NATIVE_KEYCHAIN=ON` 启用原生密钥库测试。自动化测试、实际界面检查和真实账号验收应分别记录。
