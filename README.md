# NekoTune

NekoTune 是一款本地优先的 Linux 音乐播放器，采用前后端解耦架构：C++ 后端负责播放、队列和 IPC，客户端可以按需替换。

## 当前状态

当前仓库已包含以下功能与运行方式：

- `nekotune`：统一桌面程序，在同一个进程内运行 Qt6/QML 前端，并在专用线程启动后端与 IPC 服务
- `nekotune-backend`：可选的独立 C++20 后端进程，提供基于 Unix domain socket 的 JSON-RPC API
- `nekotune-qt-qml`：可选的独立 Qt6/QML 桌面前端，只通过后端 API 交互
- 通过 Qt Multimedia 支持基础本地文件播放
- 使用 SQLite 按音频内容 hash 管理歌曲记录，保存自定义歌名、作者名和歌词，并在启动时恢复已有歌曲
- 导入时保存歌曲时长；启动扫描自动补齐旧曲库，曲库、队列与歌单无需逐首播放即可显示时长
- 文件选择器默认显示 `mp3`、`m4a`、`aac`、`wav`、`flac`、`ogg`；实际能否解码取决于本机 Qt Multimedia 后端和系统音频编解码插件
- 支持独立歌单：创建、重命名、删除、导入音乐、从队列加入、移除歌曲和整单播放；同一首歌可加入多个歌单
- 曲库保留所有已导入歌曲；可为一首歌手动设置多个标签，按多个标签同时满足筛选并播放结果，还可从曲库直接加入歌单
- 歌曲信息编辑器支持 AI 填写歌名、歌手和中文标签；先检查建议，再点击保存
- 已支持队列、单曲播放/移除、状态查询、进度、跳转、音量、上一首、下一首、停止和暂停控制
- 播放时由后端按同目录 `.krc`、`.lrc`、自定义歌词、歌词缓存、LRCLIB 顺序加载，支持 KRC 词组高亮、手动候选选择和离线缓存
- 手动搜索歌词可选 LRCLIB 或酷狗音乐；酷狗依次选择歌曲版本和歌词，优先下载并缓存 KRC，失败时回退 LRC

文件检查、SHA-256 计算与音频时长读取由导入线程执行，歌词处理保留独立线程。曲库、队列、歌单、标签和播放状态由独立服务与前端控制器管理。

后端 API 边界会保持稳定，方便后续接入 Qt/QML、Web、GTK、终端或移动端客户端。

## 构建

需要 Qt 6.6+、Zlib、FFmpeg 开发库（`libavformat`、`libavutil`，通过 `pkg-config` 查找）和 QtKeychain 0.17+ 的 Qt6 开发包（CMake 包名 `Qt6Keychain`）。凭据统一通过 [QtKeychain](https://github.com/frankosterfeld/qtkeychain) 访问系统安全存储，显式关闭明文回退：Windows 使用凭据管理器（QtKeychain 保持默认 `USE_CREDENTIAL_STORE=ON`），macOS 使用 Keychain，Linux 使用 Secret Service / KWallet。0.17+ 包含 Windows 的服务名隔离，支持本应用最大 16 KiB 的会话数据。Windows/macOS 构建无需 libsecret。

Linux 还需 libsecret 开发库（`libsecret-1`），仅用于迁移上一版存储的密钥环条目：新存储写入并回读校验成功后删除旧条目。原有明文文件的迁移规则保持不变。未解锁、访问被拒绝、服务缺失或超时均返回错误；不会写入明文备用存储。QtKeychain 操作在专用线程串行执行，每次最多等待 10 秒；超时后保留旧凭据，底层操作结束前后续请求返回忙碌错误。

Linux 凭据集成测试使用 `dbus-run-session` 与 `gnome-keyring-daemon` 创建临时密钥环，不访问桌面中的真实凭据。Windows/macOS 可用 `-DNEKOTUNE_TEST_NATIVE_KEYCHAIN=ON` 启用原生凭据存储测试，再运行 `ctest --test-dir build -R system_credential_store --output-on-failure`（多配置生成器增加 `-C Release`）。该测试使用随机临时路径作为条目标识，并在结束时清理测试条目；完整应用在 Windows/macOS 上的构建和运行仍需在对应平台验收。

```bash
cmake -S . -B build
cmake --build build
```

## 运行

桌面使用时只需启动统一程序：

```bash
./build/nekotune
```

它会在同一个进程的专用后端线程创建播放器和 IPC 服务，再在 GUI 线程加载 QML 界面，因此不需要手动分别启动前端和后端。排查歌词时间轴时，可以直接传入诊断参数：

```bash
./build/nekotune --lyrics-debug
```

使用 `--lyrics-debug` 启动后，侧边栏会显示「歌词调试」入口，可查看当前歌词时间轴、毫秒时间戳和播放进度，点击歌词行可以跳转试听。普通启动不显示该入口。

如果需要运行无界面的后端，或调试可替换客户端，仍可以分别启动：

```bash
./build/backend/nekotune-backend
./build/frontend/qt-qml/nekotune-qt-qml
```

两个进程使用相同的 Qt 本地 socket 名称：

- 如果设置了 `NEKOTUNE_SOCKET`，优先使用该值
- 否则使用默认名称 `nekotune`

在 Linux 上，Qt 会将它映射到底层 Unix domain socket，通常位于 `/tmp` 下。
统一程序仍保留这个 IPC 边界，所以外部客户端和现有 JSON-RPC 调试方式无需改变。

`build/nekotune` 是包含 QML、图片和语言文件的单个应用可执行文件；它仍依赖系统安装的 Qt、Multimedia/FFmpeg 插件和其他动态库。若要连同这些运行库一起分发，需要制作 AppImage 或使用静态 Qt 构建。

应用默认使用 `~/Music/NekoTune`，每次启动后台递归扫描音频并更新曲库，不改变队列或播放状态。独立前端连接后也会请求扫描，正在进行的请求自动合并；`config`、临时文件和目录软链接不会进入扫描范围。从曲库删除的歌曲会记录扫描忽略状态，重启不自动恢复；手动重新导入或下载可以恢复。

新下载和新添加的歌曲使用至少六位的递增编号，每首歌一个文件夹，例如 `000001/000001.mp3`，配套歌词与封面使用同一编号。编号不重复使用，重复导入按音频 SHA-256 复用。外部歌曲只对原音频建立绝对软链接；程序获取的 `.krc`、`.lrc`、`.jpg`、`.png` 或 `.webp` 是编号目录内的真实文件，不写入外部源目录。界面保留原歌名／原文件名；音频断链后保留资料和已下载的配套文件，并显示不可用。已有下载文件不会自动搬移或改名。

配置、数据库、歌词缓存和封面缓存统一放在 `~/Music/NekoTune/config`，默认数据库为 `config/nekotune.sqlite3`。首次使用默认目录会从旧数据库生成并校验一致性快照，同时迁入旧配置和缓存；旧文件保留，已有目标数据优先。配置目录权限为 `0700`。酷狗密钥和登录会话保存在系统密钥环中，按配置路径隔离；旧明文凭据确认迁入密钥环后删除（包括旧配置位置的副本），迁移失败则保留原文件并在酷狗页面提示。语言和仅本地歌词设置保存在 `config/settings.json`。

可通过 `NEKOTUNE_HOME=/path/to/music-root` 使用独立目录；显式指定此变量时不导入原用户配置。`NEKOTUNE_DB_PATH=/path/to/nekotune.sqlite3` 仍可独立覆盖数据库位置。测试和开发隔离数据时同时指定 `NEKOTUNE_HOME` 和 `NEKOTUNE_SOCKET`。

队列会和歌曲资料一起保存在 SQLite 中，重启后恢复上次的队列顺序、重复项和当前项。清空队列后，历史歌曲资料仍会保留，但不会再次自动进入队列。

歌单独立保存在 SQLite 中，清空队列不会清空歌单。从侧边栏打开歌单，使用「播放全部」按当前浏览顺序生成播放队列；在歌单内「导入音乐」只加入该歌单，不自动播放。删除歌单不影响当前队列、其他歌单或本地音乐文件。旧版文件夹首次启动时自动迁移为歌单，嵌套名称保留为「父级 / 子级」，原队列顺序和当前项保持不变。

侧边栏可直接打开曲库和歌单。曲库包含历史导入歌曲，即使它们已离开队列和歌单；曲库与歌单可搜索歌名、歌手或文件名；曲库的标签筛选位于搜索栏旁，选择多个标签时只显示同时拥有全部标签的歌曲。单击歌曲行选中，双击或按 Enter 播放，行首播放按钮可一键播放／暂停。曲库支持 Ctrl 增减选择、Shift 区间选择；搜索与标签变化会清除选择。播放全部或双击会按当前可见歌曲生成队列，切页、搜索和选择不会改变播放状态。曲库列表可逐首勾选或全选当前筛选结果，确认后批量删除，所选歌曲会从曲库、歌单及队列移除，但本地音乐文件保留。歌曲信息编辑器可增删该歌曲的标签，曲库标签筛选弹层可新建、改名或删除全局标签。曲库播放会跳过文件已不可用的歌曲并显示跳过数量；如果没有可播放歌曲，当前队列不会被替换。标签与歌单均按歌曲身份持久保存，不会随清空队列而消失。

前端支持中文和英文国际化，默认跟随系统语言；也可以在「设置 → 常规」切换，或通过 `NEKOTUNE_LANGUAGE=zh` / `NEKOTUNE_LANGUAGE=en` 在启动时指定语言。

## 界面与操作

### AI 歌曲信息填写

在「设置 → AI 歌曲信息」填写兼容 OpenAI 的 API Base URL（例如 `https://api.example.com/v1`）和模型 ID；需要鉴权时填写 API Key。保存后可「测试连接」，测试会调用一次模型。接口使用非流式 Chat Completions，地址中的路径前缀会保留。

打开一首歌的「编辑歌曲信息」，点击「AI 填写」。程序发送原始文件名、当前编辑内容、已有标签和本地歌词文字，不上传音频或文件绝对路径，不进行在线资料检索。非空建议更新歌名和歌手，新标签合并到原标签；缺乏依据的名称保持原值。结果只在编辑框预览，点击「保存」才写入曲库，歌词和音频内嵌标签不会被 AI 修改。

地址和模型保存在 `config/settings.json`，Key 保存在系统密钥库，并按配置目录及服务地址隔离。Key 输入留空表示保留当前服务已保存的 Key；切换服务不会带入原服务的 Key。免鉴权接口可直接使用，无需系统密钥库。请求最多等待 60 秒，失败可重试；生成期间播放控制仍可用，关闭窗口会丢弃返回的建议。

### 播放与曲库

启动默认打开「本地音乐」，侧边栏集中管理歌单；底部播放栏始终可达。点击封面、歌名或歌词按钮进入正在播放页，返回后恢复原浏览页面、搜索和滚动位置。右下角队列按钮展开独立的右侧抽屉；可定位当前歌曲、追加音乐、移除歌曲或确认清空队列。抽屉不遮挡播放栏。

曲库「导入音乐」只入库；歌单「导入音乐」只加入歌单；队列抽屉「添加音乐」只追加队列，均不自动切歌。歌曲右键与更多菜单可编辑信息、加入歌单或当前队列，并明确显示移除对象。停止播放位于底栏歌曲的更多菜单。

- Space：播放／暂停，编辑文字或打开弹窗时不触发。
- Ctrl+F：聚焦当前曲库、歌单、酷狗页面或队列抽屉的搜索框。
- Ctrl+O：导入到当前浏览目标；队列抽屉展开时追加队列。
- Esc：优先关闭弹窗，再收起队列，最后退出正在播放页。

酷狗页面可直接匿名搜索，登录表单位于右上角账号弹窗；未配置下载密钥时可从该弹窗前往设置。下载完成只导入曲库，分页使用已提交的搜索词，修改输入框不会改变正在浏览的结果。

## 歌词

自动加载顺序为同目录同名 `.krc` → `.lrc` → 歌曲自定义歌词 → 本地歌词缓存 → LRCLIB。`.krc` 可为酷狗二进制文件或已解码文本；损坏时继续尝试 `.lrc`。同名 `.lrc` 仍可为普通文本。点击「刷新」会跳过缓存和自定义歌词，本地同名文件仍优先。

手动打开「搜索歌词」后可选择 LRCLIB 或「酷狗音乐」。酷狗会先列出歌曲版本，再列出该版本的歌词候选；选定歌词后优先获取 KRC，失败时回退 LRC。歌曲搜索使用匿名的 [酷狗歌词 Worker](https://kugou-lyrics-api.lyuy.workers.dev)，KRC 下载使用酷狗歌词接口，无需登录或 Cookie。外部歌曲沿用播放时自动加载和手动搜索的获取时机；成功获取的歌词及对应酷狗封面写入该歌曲编号目录，手动重新选择时原子更新配套文件。扫描不会批量发起在线下载。其他本地歌曲不会自动搜索酷狗；「仅本地歌词」模式的歌词加载不会发出网络请求。

酷狗歌曲版本会显示封面缩略图；选定歌词后，曲库、歌单、队列和播放器会同步显示同一封面。后端统一优先读取音频同目录同名的 `.jpg`、`.jpeg`、`.png`、`.webp`，再使用已选歌词或歌词缓存中的封面地址，无封面时显示默认图；尚未播放的歌曲也会读取本地封面和已有歌词缓存。封面图片保存在本地磁盘缓存，歌词缓存保留封面地址。「仅本地歌词」模式下保留本地封面，停用远程封面加载。

旧版数据库中的识别任务和转写记录、本地 `.asr.json` 文件及原有设置文件不会被删除；此版本不再读取或生成 ASR 歌词。

## 酷狗音乐下载

侧边栏「酷狗音乐」支持搜歌、短信登录和下载。先在「设置」页填写与酷狗 Worker 的 `ACCOUNT_API_KEY` 相同的密钥；应用会把它保存在系统密钥环中，界面仅显示配置状态。密钥环不可用或写入失败时明确报错，不回退到明文文件。保存后立即生效，重启后继续使用；清除后回退到启动环境中的密钥。也可在启动 NekoTune 的环境里设置 `KUGOU_ACCOUNT_API_KEY`，或设置 `KUGOU_ACCOUNT_API_KEY_FILE` 指向仅自己可读的密钥文件。搜索可匿名使用，发送验证码、登录和下载需要密钥。开发时可用 `KUGOU_MUSIC_API_URL` 指定本机 Worker 地址；远程地址必须是 HTTPS。

```bash
KUGOU_ACCOUNT_API_KEY_FILE=/path/to/private-account-key ./build/nekotune
```

登录会话也保存在系统密钥环中，不会读取其他项目的 Cookie 文件。升级时自动迁移 `~/Music/NekoTune/config/kugou-session.json` 和 `kugou-account-key`；写入并回读校验成功后才删除旧文件。启动环境显式指定的密钥文件由用户管理，程序不会删除。下载使用酷狗返回的临时 HTTPS 地址与固定 `128` 音质，保存至 `~/Music/NekoTune` 下的编号文件夹。歌曲进入曲库，但不会改变当前队列或播放状态；若歌词能唯一可靠匹配，则优先在音频旁保存同名 `.krc`，并继续保存 `.lrc` 作为回退。已有歌曲不会自动补取 KRC。酷狗搜索结果提供封面时，会在音频旁保存同名 `.jpg`、`.png` 或 `.webp`，播放器优先显示本地封面，包括仅本地歌词模式。已有音频、歌词或封面文件不会被覆盖；封面获取失败不会影响歌曲导入。酷狗可能按账号、歌曲及设备拒绝提供播放地址；此时界面会报告失败原因。当前不提供 VIP 领取或升级操作。

## 路线图

Milestone 1 聚焦最小可播放产品。当前实现使用 Qt Multimedia 作为第一版播放适配层；后续可以把解码和音频输出迁移到独立的 FFmpeg、PipeWire 模块，而不影响已有前端客户端。
