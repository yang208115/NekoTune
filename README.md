# NekoTune

NekoTune 是一款本地优先的 Linux／Windows 桌面音乐播放器，使用 C++20、Qt6 和 QML。曲库、歌单、队列、歌词和配置由本机管理；外部音源扩展、在线歌词和 AI 歌曲信息填写按需使用网络服务。

桌面程序 `nekotune` 在一个进程内运行界面和后端。项目同时提供独立后端与独立前端，三种程序共用同一套本地 Socket API。

[文档导航](docs/README.md) · [扩展开发](docs/extensions.md) · [本地 API](docs/API.md) · [待办](docs/todo/README.md)

## 功能

| 功能 | 当前行为 |
| --- | --- |
| 首页 | 显示当前播放、最近加入／最近播放歌曲、歌单入口，以及近 30 天听歌热力图、本周收听时长和常听歌曲 |
| 页面导航 | 默认界面中的页面首次访问时加载，切换后保留页面实例与浏览状态；首页和侧栏可直接新建歌单 |
| 听歌历史 | 后端记录逐次播放与实际收听时长；支持今天／近 7／30 天、歌名／歌手搜索、完整播放筛选、分页及清空历史 |
| 本地曲库 | 导入音频、已登记资源的增量校验、搜索、批量选择、编辑歌曲信息；按加入顺序／歌名／歌手／专辑／时长／播放次数／最近播放排序，支持从未播放、近 7／30 天播放、入库来源与多标签组合筛选 |
| 内嵌资料 | 首次导入读取歌名、歌手、专辑、专辑歌手、流派、年份、碟号、音轨号和内嵌歌词，重复导入保留已有资料 |
| 专辑与批量编辑 | 曲库切换歌曲／专辑浏览，专辑按碟号和音轨号播放；多选后批量修改勾选字段，标签支持追加、替换或移除 |
| 歌单 | 创建、重命名、导入、添加歌曲及按当前浏览顺序播放 |
| 播放队列 | 独立抽屉，支持下一首播放、追加到末尾、拖拽重排、移除、清空和重启恢复；随机模式优先播放指定待播项 |
| 播放控制 | 播放／暂停、停止、上一首、下一首、跳转、音量；顺序、单曲循环、随机和列表循环 |
| 音频输出 | 设置页和播放栏选择系统默认或指定设备；保存选择，设备断开时暂停，重连后手动恢复 |
| 系统托盘 | 关闭窗口继续后台播放，托盘可恢复窗口、播放／暂停、切歌和退出 |
| Linux 系统媒体控制 | MPRIS 2：桌面媒体面板和媒体键控制播放、切歌、进度及音量，并显示歌曲资料与封面 |
| 歌词与封面 | 本地优先，支持 LRC、KRC 词组高亮、在线候选选择和离线缓存 |
| AI 歌曲信息 | 通过兼容 Chat Completions 的服务生成歌名、歌手和标签建议，确认后保存 |
| 扩展 | C++ 原生后台、QML 页面与完整界面替换、主题、命令、歌词及在线播放音源 |
| 语言 | 中文／英文，可在设置中切换 |

文件选择和扫描支持 `mp3`、`m4a`、`aac`、`wav`、`flac`、`ogg`；实际解码能力取决于本机 Qt Multimedia 后端及音频编解码库。

## 构建与启动

### 依赖

- CMake 3.28+、支持 C++20 的编译器和 `pkg-config`。
- Qt 6.6+：Core、Gui、Widgets、Network、Sql、Multimedia、Quick、Qml、QuickControls2、Test、QuickTest；保持音高的倍速功能需要 Qt 6.10+，Linux 发布工作流使用 6.11.2。
- Linux 桌面集成另需 Qt DBus 开发包；自动化总线测试需要 `dbus-run-session`，可选安装 `playerctl` 验证客户端互操作。
- Zlib 和 FFmpeg 开发库：`libavformat`、`libavutil`、`libavcodec`、`libswresample`、`libavfilter`。
- QtKeychain 0.17+ 的 Qt6 开发包，CMake 包名为 `Qt6Keychain`。
- Linux 还需 `libsecret-1` 开发库，用于读取并迁移旧版系统密钥库条目。建议安装 `libpulse` 14+ 开发库（Debian/Ubuntu：`libpulse-dev`），以便直接选择同一声卡下的耳机／扬声器端口；兼容 PulseAudio 和 PipeWire 的 Pulse 服务，未编入此支持时仍可选择 Qt 音频设备。
- 扩展以 C++ 原生库在后端进程内加载，不需要 Node.js。原生扩展使用 SDK 3.0.0 与清单 `apiVersion: 3`，纯界面与主题包接受 `apiVersion` 1–3。扩展运行时支持 Linux 和 Windows x86_64，扩展必须与宿主使用同一工具链和 Qt 小版本构建，详见 [扩展文档](docs/extensions.md)。

Linux 构建使用系统开发包或官方 Qt SDK；Windows 构建使用 MSYS2 UCRT64 的 GCC、CMake、Ninja、pkgconf、Qt6、QtKeychain、FFmpeg 和 Zlib。不支持 macOS。

在仓库根目录执行：

```sh
cmake -S . -B build
cmake --build build --parallel
./build/nekotune
```

启动后默认打开「首页」。QML、图片与翻译文件嵌入可执行文件，Qt、QtKeychain 和其他动态库仍需安装；当前构建产物不是包含所有运行依赖的分发包。

通过 `cmake --install build --prefix /absolute/install/path` 安装应用和扩展 SDK（`include/nekotune`、`lib/cmake/NekoTuneSDK`）。构建过程不访问网络。

### 自动构建与 Release

GitHub Actions 的 [CI 工作流](.github/workflows/ci.yml)在推送 `main`、提交 PR 或手动运行时构建并测试 Linux、Windows x64。每个平台运行 CTest，以及隔离用户目录的分发包启动检查（`scripts/ci/smoke_release.py`），分别验证独立后端与桌面程序的 SQLite、IPC、原生扩展运行时与主题导入导出，以及桌面的 QML 加载；独立 SDK 另经 `scripts/ci/smoke_sdk.py` 验证。成功的普通构建可在 Actions 页面下载应用与 SDK Artifact。

推送与 `CMakeLists.txt` 中版本一致的 `v*` 标签会触发 [Release 工作流](.github/workflows/release.yml)。标签提交须在 `main` 历史中；工作流等待该提交在 `main` 上的 CI 成功后，复用其构建产物创建 GitHub Release。发布包含 Windows ZIP、Linux TAR.GZ、两个平台各自的 SDK ZIP 和四份 SHA-256 校验文件；附件上传和校验完成后才公开 Release。更新版本时先修改 CMake 项目版本并将提交合入 `main`，再创建对应标签。已公开版本不可通过重跑覆盖，应使用新版本发布。

解压 Windows 包后运行 `bin/nekotune.exe`；解压 Linux 包后运行根目录的 `./NekoTune`。包中包含 Qt、FFmpeg、QtKeychain 和 QML 模块，无需另装 Qt。Linux 包在 Ubuntu 24.04 构建，面向 glibc 2.39+ 的 x64 桌面系统，仍需系统图形驱动、音频服务和 Secret Service 密钥库。Windows 包面向 Windows 10/11 x64。CI 使用软件渲染，Linux 使用离屏平台，Windows 使用原生窗口平台，并以 0.5 的 Qt 缩放因子在 runner 的小屏幕上覆盖 1360 像素逻辑宽度；该缩放只用于 CI。真实设备的图形驱动、音频设备和原生密钥库仍需设备验收。

Linux 包同时包含 IBus 和 Fcitx 输入上下文插件；Fcitx5-Qt 5.1.9 使用与发行包相同的 Qt 编译，不能用系统新版 Qt 的插件替换。系统仍需运行对应输入法服务，并配置 `QT_IM_MODULE=fcitx` 或 `ibus`。CI 会检查两个插件实际加载成功，候选框与中文上屏另需通过输入法交互验证。

### 分离运行

在两个终端中分别启动后端与前端：

```sh
# 终端 1
./build/backend/nekotune-backend
```

```sh
# 终端 2
./build/frontend/qt-qml/nekotune-qt-qml
```

两者默认连接名为 `nekotune`，可用 `NEKOTUNE_SOCKET` 覆盖。Linux 使用 Unix domain socket；统一桌面程序也保留此接口。相同连接名同时只能运行一个后端。

### 隔离开发数据

```sh
nekotune_profile=$(mktemp -d /tmp/nekotune-dev.XXXXXX)
NEKOTUNE_HOME="$nekotune_profile" \
NEKOTUNE_SOCKET="$nekotune_profile/nekotune.sock" \
./build/nekotune
```

此目录会保留此次运行的数据。分离运行时，两个终端必须使用相同的 `NEKOTUNE_HOME` 和 `NEKOTUNE_SOCKET`；仅改变 Socket 不会隔离曲库。

## 使用

### 倍速播放

底部播放栏的 `1.0×` 入口可选择 0.5×–2.0×（每档 0.25×），保持音高；设置页可选择速度或恢复 1.0×。速度全局保存，切歌和重启后沿用，不写入单曲。歌词与进度跟随媒体实际位置，MPRIS 只读展示当前速度。

默认播放引擎使用 FFmpeg 解码、连续 PCM 管线与 `QAudioSink` 输出，支持无缝播放、自然换曲淡入淡出和应用内 10 段 EQ。设置中的后端偏好在重启后生效；当前源尚未输出音频时，特定格式／解码初始化错误可回退 Qt 一次。

ReplayGain／响度均衡默认关闭，支持单曲、专辑和预增益；优先采用已有标签，缺少数据时可从设置页启动可取消的后台分析。结果仅存入应用缓存，播放期间降低分析负载，不修改原音频。Crossfade 两路分别应用增益，再经 EQ 和统一限幅；Qt 后端明确旁路。详见 [音频引擎](docs/audio-engine.md)。

FFmpeg 引擎当前仅支持原速，不覆盖已有倍速偏好。需要保留音高的倍速时可选择 Qt 后端并重启；该能力需要 Qt 6.10+ 和支持音高补偿的 Qt Multimedia 后端。

### 系统托盘

默认关闭主窗口后收进系统托盘，播放继续。单击或双击托盘图标恢复窗口；右键菜单提供窗口显隐、播放／暂停、上一首、下一首和退出，并显示当前歌曲。中英文菜单随设置语言切换。

设置中的「关闭窗口后收进系统托盘」可切换为关闭即退出。没有可用托盘时关闭会退出；窗口隐藏后若托盘消失，会自动恢复窗口。Linux 桌面需要提供 StatusNotifierItem 或 XEmbed 托盘支持，部分 GNOME 环境需要启用托盘扩展。托盘「退出」及 Linux MPRIS Quit 始终退出并停止内嵌后台；分离运行的客户端退出不会停止外部后台进程。

### 扩展

侧栏「扩展」支持安装 ZIP、挂载开发目录、启停、重载、配置和日志。普通扩展首次启用需要确认完整系统权限；主题包可直接启用，含代码的界面或壁纸在首次加载前需要信任。安装时不会自动运行扩展。界面替换与主题需要明确选择，`Ctrl+Shift+E` 打开独立管理窗口，`--safe-mode` 用于禁用扩展启动并恢复界面。

「扩展音源」可搜索、在线播放、加入队列／歌单及下载。纯在线记录不会混入本地曲库；来源停用或网络失败不会删除其队列及歌单记录。

主项目不包含或随应用分发第三方音源插件；插件源码、测试和 ZIP 在独立目录维护，按需导入 ZIP 或挂载开发目录。

开发模板、示例、公开 SDK 和协议说明见 [扩展开发与使用](docs/extensions.md)。

### 主题与外观

在「设置 → 外观」切换夜樱、深海、森林及其深浅配色，或选择跟随系统。配色和界面可分开选择、分别恢复默认；点击含界面的主题卡片可应用整套主题，不含界面的卡片只改变配色。主题包支持导入、导出、更新和重新加载，含代码的界面在信任后加载。

「减少动态效果」是独立保存的用户偏好，主题无法覆盖；音乐壁纸的样式与来源在壁纸设置中单独选择。主题格式、模板、打包和恢复方法见[主题制作指南](docs/themes.md)，职责约定见[主题边界规范](docs/theme-boundaries.md)。完整默认界面模板及跨 Shell 会话状态恢复仍待实现。

### 浏览与播放

单击歌曲行选中，双击或按 Enter 播放；行首播放按钮可直接播放／暂停。曲库支持 Ctrl 增减选择、Shift 区间选择。搜索或标签条件变化会清除选择；选择多个标签时，结果必须同时拥有所有所选标签。

曲库和歌单的播放操作按当前可见列表生成队列。首页「最近加入」按其展示列表播放。曲库播放会跳过不可用文件并提示数量；没有可播放歌曲时保留当前队列。切换页面、搜索和选择本身不会改变播放状态。

| 导入入口 | 结果 |
| --- | --- |
| 首页／曲库「导入音乐」 | 加入曲库 |
| 歌单「导入音乐」 | 加入曲库和该歌单 |
| 队列抽屉「添加音乐」 | 加入曲库并追加队列 |
| 扩展音源下载 | 完成后加入曲库 |

以上操作均不自动切歌。队列保存顺序、重复项和当前项；清空队列不会删除曲库或歌单。删除歌单不会删除歌曲文件，也不影响其他歌单或当前队列。

底部播放栏始终可达。点击封面、歌名或歌词按钮进入正在播放页；返回后恢复原浏览页面。队列按钮展开右侧抽屉，停止播放位于底栏歌曲的更多菜单。

| 快捷键 | 操作 |
| --- | --- |
| Space | 播放／暂停；文字编辑或弹窗活动时禁用 |
| Ctrl+F | 聚焦当前页面提供的搜索框；队列抽屉展开时优先搜索队列 |
| Ctrl+O | 向当前浏览目标导入；队列抽屉展开时追加队列 |
| Esc | 关闭弹窗，或收起队列／退出正在播放页 |

### Linux 系统媒体控制

统一程序与独立 Qt/QML 前端在连接后端并收到完整状态后，自动注册 MPRIS 会话 `org.mpris.MediaPlayer2.NekoTune`；同时打开多个前端时，后续实例使用 `.instance<PID>`。后端断线或前端退出时撤销会话，重连后重新注册。独立后端本身不注册会话；退出独立前端不会关闭独立后端。

系统媒体面板可读取歌曲资料、封面、时长和进度，控制播放、暂停、停止、切歌、跳转与音量，也可请求显示窗口或退出桌面程序。系统端切歌保留暂停／停止状态。窗口能否获得焦点由桌面窗口管理器决定。系统端循环／随机设置、队列编辑和 OpenUri 暂不提供；系统总线不可用时仅记录警告，不影响普通播放。

可选用 `playerctl --player=NekoTune status`、`playerctl --player=NekoTune metadata`、`playerctl --player=NekoTune play-pause` 检查当前会话。发行包包含 Qt DBus 运行依赖，用户会话仍需提供 D-Bus 服务。

### 迷你模式与桌面歌词

从底栏「窗口模式」、设置或系统托盘打开迷你模式。迷你窗口显示封面、歌曲、上一首／播放暂停／下一首和当前歌词，支持置顶与右下角缩放；激活窗口时可按 Space 播放／暂停。关闭迷你窗口或点击「返回主界面」会恢复原页面与主窗口状态，播放保持连续。托盘单击及系统媒体的显示请求也会恢复完整主界面。

X11 和 Windows 可打开独立透明置顶桌面歌词，显示当前行逐字高亮及下一行预告。拖动窗口调整位置，右下角调整大小；悬停后可锁定或关闭。锁定会穿透点击，从托盘或设置解锁；没有系统托盘时禁止锁定，托盘消失时自动解锁。歌词按已有 LRC／KRC 时间轴同步，纯文本仅显示首个非空行并标注无法同步。

原生 Wayland 暂不开放桌面歌词，设置显示合成器协议限制说明；音乐壁纸的可选 layer-shell 接入不改变此限制，也不会自动切换到 X11。迷你模式仍可使用，置顶效果由合成器决定。使用 XWayland（Qt `xcb` 平台）时按 X11 路径运行，实际置顶和穿透效果仍需桌面环境验收。

窗口位置、尺寸和迷你置顶偏好保存在现有配置中；重启始终显示主窗口，辅助窗口需要手动打开，桌面歌词每次打开默认解锁。深浅主题影响迷你窗口，桌面歌词使用描边文字保持透明背景下的可读性。原生置顶、透明和输入穿透以实际平台验收为准。

### 动态音乐壁纸（实验性）

设置中可运行时启停音乐壁纸，显示共享封面、播放进度与歌词，支持每屏状态和启动后恢复。Linux 使用原生 Wayland Bottom 层透明叠加，可与 Background 层的 awww 共存；Windows 保守探测 Explorer WorkerW，结构或 DPI 不兼容时显示失败。关闭不影响音乐和原桌面背景。真实频谱尚未实现，30/60 Hz 选项仅控制歌词插值，不是窗口帧率上限。

「设置 → 动态音乐壁纸 → 壁纸样式」可选择经典卡片、黑胶唱片或全屏歌词，切换立即生效并保存。黑胶随播放缓慢旋转，暂停时停转；全屏歌词放大当前行与可选下一行，支持换行及原有逐字高亮。三种样式共用窗口和播放状态。

主题包可通过顶层 `wallpaper` 字段提供完整 QML 音乐壁纸（旧写法 `ui.wallpaper` 已废弃）。可在「设置 → 外观 → 壁纸」或动态音乐壁纸设置中选择内置样式、「跟随当前主题」或任意主题的壁纸，主题切换与重新加载立即更新；未提供或加载失败时回退经典卡片并提示，保留原选择。选择主题或壁纸不会自动开启壁纸，安全模式不加载自定义壁纸。接口与示例见 [主题制作指南](docs/themes.md#主题音乐壁纸)。

编译开关为 `NEKOTUNE_ENABLE_WALLPAPER`（默认 ON）；Linux 可选依赖为与构建 Qt 匹配的 Qt 6.10+ Wayland 私有开发文件和 LayerShellQt 6.6+，缺失时播放器仍可构建。原生单屏 Niri 已进行功能检查；Windows、多屏及更多原生场景尚需验收。详见[壁纸架构、构建、发布及验证说明](docs/wallpaper.md)。

### 歌词与封面

自动加载顺序为：同目录同名 `.krc` → `.lrc` → 自定义歌词 → 歌词缓存 → 在线来源。在线优先匹配歌曲所属来源的已注册歌词提供方，无法匹配时使用 LRCLIB。损坏的 KRC 会尝试回退 LRC；「刷新」跳过自定义歌词和缓存，仍优先读取本地文件。自动在线结果只有满足可靠匹配条件才应用；分阶段来源返回多个同分歌词版本时保留原来源候选，由用户选择。扩展歌曲版本无法可靠匹配、无结果或获取失败时可回退到 LRCLIB。

手动搜索可选 LRCLIB；启用并配置酷狗插件后也可选择酷狗音乐。酷狗先选择歌曲版本，再选择歌词，优先获取 KRC，失败时回退 LRC；歌词搜索无需登录。成功获取的歌词保存到曲库数据库，封面保存为独立的内容对象；扫描不会批量获取在线资源。

曲库、歌单、队列和播放器使用后端统一解析的封面：本地同名 `.jpg`、`.jpeg`、`.png`、`.webp` 优先，其次使用已选歌词或缓存中的封面地址。「仅本地歌词」模式使用本地歌词、缓存和本地封面，停止歌词网络请求及远程封面加载。

歌词诊断页可通过以下方式启用：

```sh
./build/nekotune --lyrics-debug
```

侧边栏会显示「歌词调试」，可查看时间戳、当前进度并点击歌词行跳转。旧版 ASR 数据保留，但当前程序不再读取或生成 ASR 歌词。

### AI 歌曲信息

在「设置 → AI 歌曲信息」填写 API Base URL、模型 ID 和可选 API Key，保存后可测试连接；测试会调用一次模型。请求使用非流式 Chat Completions，并保留地址中的路径前缀。

在「编辑歌曲信息」中点击「AI 填写」。模型接收原始文件名、当前草稿、标签和本地歌词文字，不上传音频、歌曲 hash 或绝对路径，不进行在线资料检索。建议只进入编辑框；检查后点击「保存」才写入曲库，不修改音频内嵌标签。

地址和模型保存在设置文件中，Key 按配置目录和服务地址保存在系统密钥库。Key 输入留空保留当前服务的 Key，切换服务不会沿用其他服务的 Key。请求总超时为 60 秒，关闭编辑器会丢弃迟到结果；生成期间仍可控制播放。

## 数据与删除

默认目录如下：

```text
~/Music/NekoTune/
├── media/ab/<完整 SHA-256>.flac  # 独立保存的音频副本
├── artwork/ab/<封面 SHA-256>.png
├── .staging/                   # 可识别的导入、下载、恢复暂存任务
├── .rollback/                  # 恢复前的资源副本
└── config/
    ├── nekotune.sqlite3        # 歌曲、资源关联、歌词、歌单、队列与历史
    └── settings.json
```

导入会复制音频并收取原目录同名歌词、封面，不修改或移动外部原文件。移走外部原文件后，已导入歌曲仍可播放。音频按整个文件的 SHA-256 精确去重，歌曲 ID 独立保留；不同编码或不同标签的文件不会擅自合并。歌曲、歌单和队列通过资源关联解析库内相对路径，IPC 仍返回实际可播放的绝对路径。

旧编号目录、软链接和 `.audio.json` 引用在启动后按歌曲迁移。新资源校验并提交成功后清理旧托管文件，保留外部原文件和旧目录中的无关文件。离线、内容不匹配或配套资料读取失败的条目保留原记录，可在「设置 → 音乐库」查看原因并重试。正在使用的旧文件延迟清理。

启动和前端连接执行增量校验及缺失时长补全；「完整校验」逐个检查登记资源。扫描不再把根目录中的任意文件自动导入，不联网获取配套资源，也不改变队列或自动播放。添加新歌曲请使用导入入口。

曲库删除会移除歌曲及歌单、队列关联。界面默认勾选清理托管文件；API 的 `library.delete` 仍默认不清理。共享音频和封面只有在无其他歌曲引用、且未明确要求保留时才删除。文件删除和数据库事务配合持久化清理日志，失败可回滚或在重启后继续处理。外部原文件始终保留。

曲库支持导出所选歌曲，歌单支持按原顺序导出，并生成相对路径 M3U8。每次建立独立导出目录，按当前“歌手 - 歌名”命名，附带歌词和封面。音频字节保持不变，不改写内嵌标签；缺失或纯在线歌曲列入跳过结果，不自动下载。

「设置 → 音乐库」提供目录备份与恢复。备份包含 SQLite 一致快照、音频、封面和校验清单，保留歌单、标签、队列及播放历史，不包含账号密钥、插件、应用设置和临时缓存。待迁移的外部引用必须先处理。恢复前展示摘要并校验全部文件；确认后停止播放、替换曲库并重建后端会话，恢复前副本保留供回退。回退副本可在设置中显式清理。详见[音乐库存储与恢复](docs/library-storage.md)。

首次使用默认目录会迁移旧数据库、配置和缓存，保留旧数据库及已有目标数据；旧明文凭据只有在系统密钥库写入并回读校验成功后才删除。配置目录权限为 `0700`。密钥库不可用或拒绝访问时会报错，不回退明文存储。

| 环境变量 | 用途 |
| --- | --- |
| `NEKOTUNE_HOME` | 覆盖音乐根目录；显式设置时不迁入原用户配置 |
| `NEKOTUNE_DB_PATH` | 单独覆盖 SQLite 路径，不改变音乐和缓存目录 |
| `NEKOTUNE_SOCKET` | 覆盖本地 Socket 名称或路径 |
| `NEKOTUNE_LANGUAGE` | 指定 `zh`／`en`，优先于保存的设置和系统语言 |

## 开发与验证

```sh
QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software \
ctest --test-dir build --output-on-failure
git diff --check
```

Linux 密钥库相关集成测试通过 `dbus-run-session` 和 `gnome-keyring-daemon` 创建临时密钥环；缺少这些运行工具时，相应测试标记为跳过。Windows 可用 `-DNEKOTUNE_TEST_NATIVE_KEYCHAIN=ON` 启用原生密钥库测试。自动化测试、实际界面检查和真实账号验收应分别记录。
