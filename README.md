# NekoTune

NekoTune 是一款本地优先的 Linux 音乐播放器，采用前后端解耦架构：C++ 后端负责播放、队列和 IPC，客户端可以按需替换。

## 当前状态

当前仓库已包含以下功能与运行方式：

- `nekotune`：统一桌面程序，在同一个进程内运行 Qt6/QML 前端，并在专用线程启动后端与 IPC 服务
- `nekotune-backend`：可选的独立 C++20 后端进程，提供基于 Unix domain socket 的 JSON-RPC API
- `nekotune-qt-qml`：可选的独立 Qt6/QML 桌面前端，只通过后端 API 交互
- 通过 Qt Multimedia 支持基础本地文件播放
- 使用 SQLite 按音频内容 hash 管理歌曲记录，保存自定义歌名、作者名和歌词，并在启动时恢复已有歌曲
- 文件选择器默认显示 `mp3`、`m4a`、`aac`、`wav`、`flac`、`ogg`；实际能否解码取决于本机 Qt Multimedia 后端和系统音频编解码插件
- 支持独立歌单：创建、重命名、删除、导入音乐、从队列加入、移除歌曲和整单播放；同一首歌可加入多个歌单
- 曲库保留所有已导入歌曲；可为一首歌手动设置多个标签，按多个标签同时满足筛选并播放结果，还可从曲库直接加入歌单
- 已支持队列、单曲播放/移除、状态查询、进度、跳转、音量、上一首、下一首、停止和暂停控制
- 播放时由后端按同目录 `.krc`、`.lrc`、自定义歌词、歌词缓存、LRCLIB 顺序加载，支持 KRC 词组高亮、手动候选选择和离线缓存
- 手动搜索歌词可选 LRCLIB 或酷狗音乐；酷狗依次选择歌曲版本和歌词，优先下载并缓存 KRC，失败时回退 LRC

文件检查与 SHA-256 计算由导入线程执行，歌词处理保留独立线程。曲库、队列、歌单、标签和播放状态由独立服务与前端控制器管理。

后端 API 边界会保持稳定，方便后续接入 Qt/QML、Web、GTK、终端或移动端客户端。

```bash

```

## 运行

桌面使用时只需启动统一程序：

```bash
./build/nekotune
```

它会在同一个进程的专用后端线程创建播放器和 IPC 服务，再在 GUI 线程加载 QML 界面，因此不需要手动分别启动前端和后端。排查歌词时间轴时，可以直接传入诊断参数：

```bash
./build/nekotune --lyrics-debug
```

使用 `--lyrics-debug` 启动后，侧边栏会显示「歌词调试」入口，可查看当前歌词时间轴、毫秒时间戳和播放进度，点击歌词行可以跳转试听。普通启动不显示该入口。

如果需要运行无界面的后端，或调试可替换客户端，仍可以分别启动：

```bash
./build/backend/nekotune-backend
./build/frontend/qt-qml/nekotune-qt-qml
```

两个进程使用相同的 Qt 本地 socket 名称：

- 如果设置了 `NEKOTUNE_SOCKET`，优先使用该值
- 否则使用默认名称 `nekotune`

在 Linux 上，Qt 会将它映射到底层 Unix domain socket，通常位于 `/tmp` 下。
统一程序仍保留这个 IPC 边界，所以外部客户端和现有 JSON-RPC 调试方式无需改变。

`build/nekotune` 是包含 QML、图片和语言文件的单个应用可执行文件；它仍依赖系统安装的 Qt、Multimedia/FFmpeg 插件和其他动态库。若要连同这些运行库一起分发，需要制作 AppImage 或使用静态 Qt 构建。

开发环境默认 SQLite 数据库位于 `build/nekotune.sqlite3`，避免写入用户数据目录。可以通过 `NEKOTUNE_DB_PATH=/path/to/nekotune.sqlite3` 显式指定数据库位置。

队列会和歌曲资料一起保存在 SQLite 中，重启后恢复上次的队列顺序、重复项和当前项。清空队列后，历史歌曲资料仍会保留，但不会再次自动进入队列。

歌单独立保存在 SQLite 中，清空队列不会清空歌单。从侧边栏打开歌单，使用「播放全部」按当前浏览顺序生成播放队列；在歌单内「导入音乐」只加入该歌单，不自动播放。删除歌单不影响当前队列、其他歌单或本地音乐文件。旧版文件夹首次启动时自动迁移为歌单，嵌套名称保留为「父级 / 子级」，原队列顺序和当前项保持不变。

侧边栏可直接打开曲库和歌单。曲库包含历史导入歌曲，即使它们已离开队列和歌单；曲库与歌单可搜索歌名、歌手或文件名；曲库的标签筛选位于搜索栏旁，选择多个标签时只显示同时拥有全部标签的歌曲。单击歌曲行选中，双击或按 Enter 播放，行首播放按钮可一键播放／暂停。曲库支持 Ctrl 增减选择、Shift 区间选择；搜索与标签变化会清除选择。播放全部或双击会按当前可见歌曲生成队列，切页、搜索和选择不会改变播放状态。曲库列表可逐首勾选或全选当前筛选结果，确认后批量删除，所选歌曲会从曲库、歌单及队列移除，但本地音乐文件保留。歌曲信息编辑器可增删该歌曲的标签，曲库标签筛选弹层可新建、改名或删除全局标签。曲库播放会跳过文件已不可用的歌曲并显示跳过数量；如果没有可播放歌曲，当前队列不会被替换。标签与歌单均按歌曲身份持久保存，不会随清空队列而消失。

前端支持中文和英文国际化，默认跟随系统语言；也可以在「设置 → 常规」切换，或通过 `NEKOTUNE_LANGUAGE=zh` / `NEKOTUNE_LANGUAGE=en` 在启动时指定语言。

## 界面与操作

启动默认打开「本地音乐」，侧边栏集中管理歌单；底部播放栏始终可达。点击封面、歌名或歌词按钮进入正在播放页，返回后恢复原浏览页面、搜索和滚动位置。右下角队列按钮展开独立的右侧抽屉；可定位当前歌曲、追加音乐、移除歌曲或确认清空队列。抽屉不遮挡播放栏。

曲库「导入音乐」只入库；歌单「导入音乐」只加入歌单；队列抽屉「添加音乐」只追加队列，均不自动切歌。歌曲右键与更多菜单可编辑信息、加入歌单或当前队列，并明确显示移除对象。停止播放位于底栏歌曲的更多菜单。

- Space：播放／暂停，编辑文字或打开弹窗时不触发。
- Ctrl+F：聚焦当前曲库、歌单、酷狗页面或队列抽屉的搜索框。
- Ctrl+O：导入到当前浏览目标；队列抽屉展开时追加队列。
- Esc：优先关闭弹窗，再收起队列，最后退出正在播放页。

酷狗页面可直接匿名搜索，登录表单位于右上角账号弹窗；未配置下载密钥时可从该弹窗前往设置。下载完成只导入曲库，分页使用已提交的搜索词，修改输入框不会改变正在浏览的结果。

## 歌词

自动加载顺序为同目录同名 `.krc` → `.lrc` → 歌曲自定义歌词 → 本地歌词缓存 → LRCLIB。`.krc` 可为酷狗二进制文件或已解码文本；损坏时继续尝试 `.lrc`。同名 `.lrc` 仍可为普通文本。点击「刷新」会跳过缓存和自定义歌词，本地同名文件仍优先。

手动打开「搜索歌词」后可选择 LRCLIB 或「酷狗音乐」。酷狗会先列出歌曲版本，再列出该版本的歌词候选；选定歌词后优先获取 KRC，失败时回退 LRC。歌曲搜索使用匿名的 [酷狗歌词 Worker](https://kugou-lyrics-api.lyuy.workers.dev)，KRC 下载使用酷狗歌词接口，无需登录或 Cookie。其他本地歌曲不会自动搜索酷狗；「仅本地歌词」模式的歌词加载不会发出网络请求。

酷狗歌曲版本会显示封面缩略图；选定歌词后，曲库、歌单、队列和播放器会同步显示同一封面。后端统一优先读取音频同目录同名的 `.jpg`、`.jpeg`、`.png`、`.webp`，再使用已选歌词或歌词缓存中的封面地址，无封面时显示默认图；尚未播放的歌曲也会读取本地封面和已有歌词缓存。封面图片保存在本地磁盘缓存，歌词缓存保留封面地址。「仅本地歌词」模式下保留本地封面，停用远程封面加载。

旧版数据库中的识别任务和转写记录、本地 `.asr.json` 文件及原有设置文件不会被删除；此版本不再读取或生成 ASR 歌词。

## 酷狗音乐下载

侧边栏「酷狗音乐」支持搜歌、短信登录和下载。先在「设置」页填写与酷狗 Worker 的 `ACCOUNT_API_KEY` 相同的密钥；应用会把它保存在用户配置目录 `NekoTune/kugou-account-key` 中，文件权限为 `0600`，界面仅显示配置状态。保存后立即生效，重启后继续使用；清除后回退到启动环境中的密钥。也可在启动 NekoTune 的环境里设置 `KUGOU_ACCOUNT_API_KEY`，或设置 `KUGOU_ACCOUNT_API_KEY_FILE` 指向仅自己可读的密钥文件。搜索可匿名使用，发送验证码、登录和下载需要密钥。开发时可用 `KUGOU_MUSIC_API_URL` 指定本机 Worker 地址；远程地址必须是 HTTPS。

```bash
KUGOU_ACCOUNT_API_KEY_FILE=/path/to/private-account-key ./build/nekotune
```

登录会话单独保存在用户数据目录的 `NekoTune/kugou-session.json`，不会读取其他项目的 Cookie 文件。下载使用酷狗返回的临时 HTTPS 地址与固定 `128` 音质，保存至系统音乐目录的 `NekoTune` 文件夹。歌曲进入曲库，但不会改变当前队列或播放状态；若歌词能唯一可靠匹配，则优先在音频旁保存同名 `.krc`，并继续保存 `.lrc` 作为回退。已有歌曲不会自动补取 KRC。酷狗搜索结果提供封面时，会在音频旁保存同名 `.jpg`、`.png` 或 `.webp`，播放器优先显示本地封面，包括仅本地歌词模式。已有音频、歌词或封面文件不会被覆盖；封面获取失败不会影响歌曲导入。酷狗可能按账号、歌曲及设备拒绝提供播放地址；此时界面会报告失败原因。当前不提供 VIP 领取或升级操作。

## 路线图

Milestone 1 聚焦最小可播放产品。当前实现使用 Qt Multimedia 作为第一版播放适配层；后续可以把解码和音频输出迁移到独立的 FFmpeg、PipeWire 模块，而不影响已有前端客户端。
