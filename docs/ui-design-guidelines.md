# NekoTune UI 设计规范

版本：v1.0 · 2026-10-01

设计主题：夜樱电台 · 深色二次元音乐空间

适用范围：NekoTune Linux 桌面客户端、Qt6/QML 界面及后续相关视觉资产。

本文定义后续界面设计和实现的目标。文中的颜色、尺寸、组件状态及新增体验要求属于设计约定，不代表当前界面已经全部实现。当前项目结构以仓库代码为依据；本次仅交付规范，不修改播放器行为。

## 1. 视觉方向

**以接近黑色的紫灰作为底色，以月光紫作为主要交互色，以樱花粉作为情绪点缀，结合日系插画、清晰的音乐信息和舒展的歌词排版。**

整体感受应当是安静、柔和、有陪伴感。打开应用时，先看到正在听的音乐，再感受到夜色、插画和猫系品牌细节。

| 维度 | 设计要求 |
| --- | --- |
| 二次元气质 | 日系插画、耳机与音乐意象、夜空与月光、少量猫耳或猫爪细节 |
| 深色气质 | 带紫灰色相的多级深色表面，避免全屏使用相同黑色 |
| 主要视觉焦点 | 播放按钮、歌曲封面、当前歌词；不同页面各有主次 |
| 装饰密度 | 装饰集中在封面、页面头图与空状态，列表和控制区保持简洁 |
| 形状语言 | 柔和圆角、细线图标、轻薄分隔线，避免每个区域都套多层卡片 |
| 色彩比例 | 常规控件区域约 85% 深色中性色、10% 紫色、5% 粉色与状态色；歌曲封面不受此比例限制 |
| 风格边界 | 避免高饱和霓虹铺满页面、持续闪烁、密集粒子、整页强玻璃模糊和大面积花体字 |

猫系元素应形成品牌识别，例如默认封面的耳机猫娘、空状态中的小猫和品牌标记。播放、删除、搜索等功能仍使用明确的通用图标。

## 2. 页面结构与功能边界

沿用现有的「左侧导航 + 主内容区 + 底部播放栏」。主内容区在队列、媒体库和歌词之间切换，底部播放控制始终可达。

| 区域 | 信息与职责 | 视觉重点 |
| --- | --- | --- |
| 左侧导航 | 品牌、队列／媒体库／歌词入口、标签与歌单、连接状态、语言切换 | 稳定、低干扰，当前入口清晰 |
| 队列／歌单页 | 队列与歌单切换、曲目列表、导入、歌单管理 | 页面标题、当前播放项、主要操作 |
| 媒体库页 | 本地歌曲、标签筛选、导入与歌曲信息编辑 | 筛选结果、歌曲状态 |
| 歌词页 | 封面、歌名、作者、歌词、歌词搜索与刷新 | 封面与当前歌词 |
| 底部播放栏 | 当前歌曲、播放控制、进度、音量、歌词入口 | 播放／暂停按钮与进度 |
| 弹窗与菜单 | 歌曲信息编辑、歌单操作、歌词候选选择 | 当前任务与提交结果 |

设计实施必须保留以下语义：

- 播放队列与持久歌单相互独立；清空队列不清空歌单。
- 删除歌单不删除本地音乐文件；从队列或歌单移除歌曲时，要明确操作对象。
- 沿用现有歌曲行单击播放行为；不能仅因换肤改成双击播放。
- 保留上一首、下一首、播放／暂停、停止、跳转、音量、歌曲信息编辑和歌词搜索能力。
- 保留中文／英文切换、仅本地歌词模式和歌词来源选择。酷狗搜索继续呈现「歌曲版本 → 歌词候选」两步选择。
- 「歌词调试」仅在已有调试启动条件下出现，不成为普通导航项目。
- 当前版本已不再读取或生成 ASR 歌词；本规范不设计 ASR 入口、识别进度或逐词转写效果。

后文要求的键盘焦点、减少动态效果、提交失败保留输入等行为，需要在实施时核对和补齐。没有实现的能力不显示可点击的空入口。

### 2.1 酷狗音乐 PC 界面参考（2026-10-01）

参考[酷狗音乐 PC 官方下载页的客户端展示图](https://download.kugou.com/pc.html)与[酷狗 V20 沉浸式播放页展示图](https://img.3dmgame.com/uploads/images/xiaz/20250314/1741919166_783812.png)。后者为 2025 年的宣传截图，只作为播放页构图参考，不据此判断当前版本功能。

| 观察到的布局 | NekoTune 的落地方式 |
| --- | --- |
| 左侧导航把主要入口和个人列表分层；中间内容随入口切换 | 保持「队列／媒体库／歌词」为明确的一级入口；标签、歌单归在个人内容下。当前侧栏歌单与队列页内的横向歌单切换重复，后续以侧栏为主要入口，队列页只保留当前列表名称和操作。 |
| 主页面用封面、标题和内容分组建立浏览顺序 | 媒体库优先显示本地歌曲与标签筛选；队列页优先显示当前列表和歌曲行。借用清楚的层级，不添加在线推荐、榜单或无数据支撑的卡片。 |
| 沉浸播放页左侧突出封面，右侧集中展示歌词，控制区沿底边固定 | 歌词页延续现有「封面＋歌曲信息／歌词」分区；增强当前歌词、上下文和封面之间的主次。全局底栏保持固定，切页后播放控制位置不变。 |
| 播放栏把歌曲信息、播放／跳转和次级工具分开 | 歌曲信息靠左，主播放控件居中，音量和视图操作靠右；进度条必须有足够拖动区域，窄窗口先收缩次级操作。 |

借鉴信息架构和视觉层级，继续使用本规范的夜樱紫灰色系与原创猫系资产；不复制酷狗的蓝白配色、品牌图、在线服务入口或宣传内容。

## 3. 颜色系统

颜色使用语义名称统一管理。表中颜色均为不透明 sRGB 色值；透明度和叠加效果单独定义。

### 3.1 背景与文字

| Token | 色值 | 用途 |
| --- | --- | --- |
| `bg.canvas` | `#0E0D14` | 窗口底色 |
| `bg.sidebar` | `#121019` | 左侧导航、底部播放栏 |
| `bg.surface` | `#17141F` | 内容表面、列表基底、输入框 |
| `bg.raised` | `#211C2D` | 弹窗、菜单、浮层 |
| `bg.hover` | `#2A2338` | 普通控件悬停 |
| `bg.selected` | `#322743` | 当前入口、当前歌曲底色 |
| `border.subtle` | `#332C41` | 装饰分隔线、非关键卡片边框 |
| `border.control` | `#8D809F` | 需要靠轮廓识别的输入框与控件边界 |
| `text.primary` | `#F5F1FA` | 歌名、标题、当前歌词 |
| `text.secondary` | `#D7CFE2` | 正文、作者、普通歌词 |
| `text.muted` | `#AAA0B8` | 时间、说明、占位提示、来源信息 |
| `text.disabled` | `#736A83` | 仅用于不可操作控件的文字与图标 |
| `text.onAccent` | `#21172F` | 浅紫或浅粉实色按钮上的文字与图标 |

### 3.2 品牌与状态

| Token | 色值 | 用途 |
| --- | --- | --- |
| `accent.primary` | `#CBB8FF` | 主按钮、进度填充、焦点环、当前项标记 |
| `accent.hover` | `#DBCDFF` | 主按钮悬停 |
| `accent.pressed` | `#B7A0ED` | 主按钮按下 |
| `accent.secondary` | `#E8A9C3` | 插画呼应、标签点缀、小面积装饰 |
| `status.success` | `#98D8BC` | 已完成、连接正常 |
| `status.warning` | `#E8C58A` | 文件不可用、需要注意的状态 |
| `status.error` | `#FF9BAE` | 错误、破坏性操作提示 |
| `status.errorBg` | `#38202B` | 错误消息和危险操作的深色背景 |
| `status.info` | `#A9C8F5` | 中性提示与处理中信息 |

使用规则：

- 主操作使用浅紫实色背景和深色文字，不在浅紫按钮上使用白字。
- 樱花粉默认承担装饰作用；错误必须额外带图标和文字，不能仅用粉色表达。
- 每个任务区域最多一个填充式主要操作，其他操作使用描边或透明按钮。全局播放按钮独立保留强调。
- 只有装饰边界使用 `border.subtle`；输入框、焦点和关键图标不能依赖近乎不可见的边线。
- 渐变仅用于插画底板、头图或封面外的环境光；正文和列表使用稳定底色。
- 深色遮罩使用 `bg.canvas`、70% 不透明度。环境光通常为 6%–10% 不透明度，局部最多 16%，不覆盖文字。

### 3.3 对比度约定

项目采用正文至少 **4.5:1**、识别操作所必需的图标和控件边界至少 **3:1** 的设计目标，参考 [W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)及[非文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。本项目对大字也统一使用 4.5:1 的文字目标，便于实现和验收。

以下值按本规范不透明色值计算，显示值保留两位小数，判定使用未舍入值：

| 前景／背景 | 对比度 | 结论 |
| --- | --- | --- |
| `text.primary` / `bg.surface` | 16.30:1 | 可用于标题和正文 |
| `text.muted` / `bg.raised` | 6.64:1 | 可用于弹窗说明 |
| `text.muted` / `bg.selected` | 5.59:1 | 可用于选中行的次要信息 |
| `text.onAccent` / `accent.primary` | 9.64:1 | 可用于主按钮 |
| `border.control` / `bg.selected` | 3.80:1 | 可用于必要控件边界 |

给文字叠加透明度、图片背景或动态取色后，必须重新计算最终组合。非当前歌词仍属于阅读内容，不能使用禁用色或整体降低透明度来处理。

## 4. 字体与排版

优先使用系统无衬线字体，保证中文、英文、日文歌名和符号可以正常回退。系统已安装时可选用 Noto Sans CJK SC；字体缺失时继续使用系统字体，不阻断启动。

| 层级 | 字号／字重 | 使用位置 |
| --- | --- | --- |
| 页面标题 | 24 / 600 | 队列、歌单标题 |
| 主要歌名 | 22 / 600 | 歌词页歌曲信息 |
| 弹窗标题 | 18 / 600 | 编辑、搜索、确认弹窗 |
| 正文 | 14 / 400 | 曲目、输入内容、按钮文字 |
| 次要正文 | 13 / 400 | 作者、专辑、候选说明 |
| 辅助信息 | 12 / 400 | 时间、来源、统计、提示 |
| 歌词 | 宽窗口 24；紧凑窗口 20 | 当前行 600，其余行 400 |

所有字号为 Qt 逻辑像素基准值，不额外乘以显示器设备像素比。正文行高约为字号的 1.5 倍，歌词约为 1.6 倍；高度同时考虑字体实际度量和换行。

- 功能文案不小于 12；长歌名不通过无限缩小字号解决。
- 列表歌名一行省略，歌词页歌名最多两行；悬停和键盘聚焦都应能查看完整内容。
- 歌词完整换行，不横向跑马灯，不裁掉日文假名、中文标点和拉丁字母下伸部。
- 当前歌词用颜色与字重区分，不改变字号或对文字做缩放，避免切换时上下跳动。
- 时间采用等宽数字或等宽字体，避免播放时宽度不断变化。
- 英文品牌字标可以适度增加字距；中文按钮和正文保持自然字距。
- 不将正常歌名、歌词或错误消息烘焙进图片，保证可选择、可访问和可国际化。

## 5. 尺寸、间距与窗口适配

间距基于 4 的倍数：`4 / 8 / 12 / 16 / 24 / 32 / 48`。紧密关联元素使用 4–8，同一组件内部使用 12–16，组件与页面分区使用 24–32。

| 项目 | 目标值 |
| --- | --- |
| 默认窗口 | 1360 × 860，沿用当前基准 |
| 最小窗口 | 1000 × 640，沿用当前限制 |
| 左侧栏 | 宽窗口 220；窗口宽度小于 1200 时 180 |
| 页面内边距 | 宽窗口 24；紧凑窗口 16 |
| 底部播放栏 | 96，替代当前 82 的设计目标 |
| 歌曲行 | 最小高度 60，内部水平间距 12 |
| 常规按钮／输入框 | 最小高度 40 |
| 图标按钮 | 默认命中区域 40 × 40；密集区域下限 32 × 32 |
| 主要播放按钮 | 48 × 48 |
| 列表缩略图／底栏封面 | 40 × 40 / 48 × 48 |
| 歌词页封面 | 宽窗口 280–320；紧凑窗口 224 |
| 圆角 | 输入与小按钮 8；歌曲行与普通卡片 12；封面与弹窗 16；主播放按钮圆形 |

### 5.1 队列与歌单页

页面从上到下为头部信息、歌曲列表。头部在宽窗口可容纳 80–96 的封面和最多 144 高的插画背景；最小窗口采用约 104 高的紧凑头部，给列表保留空间。

当前实现同时在侧栏和队列页提供歌单切换。后续以侧栏歌单作为主要入口，队列页标题显示当前歌单并保留管理操作；移除重复的横向切换条时，须确保「队列」和每个歌单仍可从侧栏直接到达。歌单过多时侧栏可纵向滚动，当前歌单切换后自动进入可见区域，键盘也能到达溢出项目。

歌曲行按「序号或播放状态 → 封面 → 歌名与作者 → 时长 → 操作」排列。窄窗口优先省略次要描述和缩短标题，更多操作合并到菜单；不隐藏歌曲名、播放入口和时长。未取得时长显示 `--:--`，不伪造 `00:00`。

### 5.2 歌词页

主区域使用「左侧封面与歌曲信息 + 右侧歌词」。两区间距为 24–32，歌词区占剩余宽度。封面下方依次显示歌名、作者、可用时的专辑信息和编辑入口。

当前歌词的视觉锚点位于歌词可视区域高度的约 42%，上下保留上下文。窗口缩小时，先缩小封面和间距，再调整歌词字号；不把歌词压成狭窄竖列。

### 5.3 底部播放栏

左侧歌曲信息宽 220–280，中间播放控制弹性扩展，右侧音量和视图切换宽 160–220。上排放上一首、播放／暂停、下一首与停止，下排放时间和进度条。

在 1000 宽窗口，左右两组分别使用约 220 与 160，左右内边距 16，组间距 16，中间仍保留足够进度操作空间。音量条可缩短至 72，不遮挡播放控制。

窗口高度不足时，内容区域单独滚动，播放栏固定。100%、125%、150%、200% 显示缩放和中英文都要验证；应用内文字放大导致拥挤时，增加行高、允许表单滚动，不能直接裁切。

## 6. 插画、封面与图标

### 6.1 二次元资产风格

品牌插画统一使用柔和日系绘制风格：清晰但不过硬的轮廓、低饱和紫粉光照、简洁背景、适量夜空与音乐元素。猫系角色可以佩戴耳机，表情安静自然。

| 资产 | 构图与交付要求 | 使用限制 |
| --- | --- | --- |
| 默认封面 | 1:1，建议 1024 × 1024；耳机猫娘或猫系音乐主题，主体位于中央安全区域 | 仅用于无封面或加载失败，不覆盖已有歌曲封面 |
| 歌单头图 | 约 4:1，建议 1600 × 400；文字所在左侧低细节，角色或景物偏右 | 必须有稳定深色底板保证标题可读 |
| 空状态插画 | 透明背景，建议 512 × 512；单个角色或物件 | 实际显示约 120–160，避免占满内容区 |
| 品牌标记 | 简化猫耳与音符关系，提供矢量或多尺寸资源 | 24–32 大小时仍能辨认 |

默认封面的大主体尽量落在中央约 70% 区域；交付时检查 48 × 48 的缩略图效果。所有插画单独保存，不把按钮或文字画进插画。使用可随项目分发的原创或获授权资源，并在资源目录记录来源。

仓库当前默认封面是紫灰色月夜山水图，可在新插画准备完成前继续作为回退资源；目标二次元封面属于后续待制作资产。

### 6.2 封面呈现

- 封面维持 1:1，不拉伸；裁切优先保留主体。
- 原歌曲封面保留自身颜色，主题通过外围底色和环境光协调，不给所有封面强制染紫。
- 加载期间保持相同尺寸，加载失败稳定显示默认封面，不让页面抖动。
- 切歌立即清除不属于新歌曲的远程封面；结果必须与当前歌曲身份匹配。
- 底部小封面不加大面积光晕；歌词页封面允许一层静态柔光。
- 默认不旋转唱片、不持续呼吸缩放、不做鼠标视差。

### 6.3 图标

图标基于统一的 24 单位网格，常用显示尺寸 18–20，线宽约 1.75–2，端点圆润。播放／暂停允许使用实心图形，其他图标使用一致线性风格。

全项目使用同一套图标或统一的现有绘制规则。不得用 Emoji 或字体字符替代删除、音量、返回等关键图标。每个无文字按钮同时提供工具提示、可访问名称和可见键盘焦点。

## 7. 组件与状态

### 7.1 按钮与导航

| 状态 | 视觉规则 | 行为规则 |
| --- | --- | --- |
| 默认 | 主按钮使用品牌色；次按钮使用深色表面或透明背景 | 名称描述具体动作 |
| 悬停 | 主按钮使用 `accent.hover`；次按钮使用 `bg.hover` | 不移动布局，不让邻近按钮位移 |
| 按下 | 主按钮使用 `accent.pressed`；次按钮使用 `bg.selected` | 可以短暂调整内部图标，不改变命中区域 |
| 键盘焦点 | 外侧 2 的品牌色焦点环，间隔 2 | 与悬停、选中状态可同时存在 |
| 当前／选中 | `bg.selected` + 紫色短标记 + 较高字重 | 同时提供选中语义，不只改变颜色 |
| 禁用 | 使用禁用色，取消悬停和按下反馈 | 必要时在附近说明条件，例如「添加音乐后即可播放」 |
| 处理中 | 保持原尺寸，显示进度图标与明确文字 | 防止重复提交；不要把整个应用锁住 |

当前导航项采用左侧约 3 宽的短标记；当前播放行采用独立播放标记与整行浅紫底色。键盘焦点不是当前播放状态，两者不能混用。

### 7.2 歌曲行与操作菜单

当前歌曲行显示播放或暂停状态；未播放时不运行假的均衡器动画。非当前歌曲悬停时可显示播放入口，播放、编辑、加入歌单、移除操作在键盘聚焦时也必须可达。

行内按钮点击不得继续触发行点击，避免「点击删除同时开始播放」。保持现有单击歌曲行播放行为；删除、更多菜单等操作拥有独立命中区域。

危险操作位于菜单底部，使用分隔线与错误色文字。删除歌单确认文案明确说明影响范围；清空队列的反馈也必须说明不会删除歌单或本地文件。没有后端支持时不显示「撤销」。

### 7.3 进度与音量滑块

进度轨道视觉高度为 4，命中区域高度至少 24；滑块可见圆点 10，悬停或拖动时为 14。滑块布局占位保持固定，只有内部圆点变化，防止坐标映射移动。

- 点击轨道一次即可定位，不能要求第二次点击。
- 拖动期间立即显示预览时间，并由手势位置控制滑块；旧播放状态回报不能把它拉回。
- 松开后提交最终跳转位置，确认期间保留目标位置；失败时恢复真实状态并提示。
- 拖动不触发自动播放或暂停；原播放状态保持一致。
- 时长未知或不可跳转时显示原因并禁用进度操作。
- 音量为零必须如实显示；不能将零当作缺省音量。支持键盘调整和读出当前值。

### 7.4 弹窗、输入框与菜单

常规表单宽度为 480–560，歌词候选弹窗可为 640–760；宽高均受窗口限制，距边缘至少 24。内容过长时内部滚动，标题和操作区保持可达。

弹窗使用 `bg.raised`、16 圆角、24 内边距和一层柔和阴影。菜单使用相同色系、12 圆角和至少 36 高的菜单项。应用内弹窗统一深色样式；系统文件选择器尊重桌面环境。

表单有可见字段标签，占位符只提供示例，不能代替标签。输入错误使用错误边线、图标和字段下方说明，并保留已输入内容。

提交成功后关闭弹窗；失败时保留输入、给出原因并允许重试。Esc 关闭未修改的普通浮层，存在未提交编辑时应防止静默丢失。模态窗口限定焦点范围，关闭后焦点回到原触发控件。

错误详情允许展开或复制；普通编辑流程不默认展示数据库路径、IPC 名称等实现信息。

## 8. 歌词体验

同步歌词以整行为单位高亮。当前行使用 `text.primary` 或 `accent.primary`，临近行使用 `text.secondary`，较远但仍可阅读的行使用 `text.muted`。纯文本歌词保持普通滚动阅读，不模拟时间轴。

自动跟随使用平缓滚动。用户手动滚动时暂停自动跟随，停止操作约 3.5 秒后恢复，沿用当前时间基准；恢复计时从最后一次有效滚动结束计算，手势仍在进行时不抢回位置。

点击有有效时间戳的歌词行可跳转，悬停或聚焦时显示可点击反馈。普通文本行没有伪造的跳转入口。前奏、间奏或暂时没有下一句时保持稳定，避免持续闪烁「加载中」。

歌词加载、搜索和失败状态在歌词区域内处理，不阻断本地音频播放。搜索来源与结果步骤有明确标题；切换歌曲后，旧歌曲的搜索结果不能覆盖新歌曲。歌词实际来源可作为辅助信息显示，不占据主标题。

## 9. 空状态、错误与文案

| 场景 | 主文案示例 | 操作与展示 |
| --- | --- | --- |
| 队列为空 | 「把喜欢的音乐放进来」 | 插画 + 「添加音乐」；保留创建歌单的次要入口 |
| 歌单为空 | 「这个歌单还很安静」 | 「添加音乐」，明确加入当前歌单 |
| 暂无歌词 | 「暂时没有找到歌词」 | 提供「搜索歌词」或已有的歌词编辑入口 |
| 仅本地歌词 | 「仅使用本地歌词」 | 非错误状态，避免提示必须联网 |
| 正在搜索 | 「正在查找歌词…」 | 局部进度反馈，允许继续控制播放 |
| 搜索失败 | 「歌词搜索失败，请重试」 | 原因摘要 + 重试；已有可用歌词继续显示 |
| 文件不可用 | 「找不到这个音频文件」 | 标记受影响歌曲，允许查看路径或移除 |
| 播放服务断开 | 「播放服务连接已断开」 | 禁用依赖服务的操作，保留列表与已有信息 |

操作文案优先使用「添加音乐」「播放歌单」「从队列移除」「删除歌单」等具体动词。空状态可以温柔、轻微拟人；错误与删除确认保持直白，不用卖萌文案替代解释。

「无网络」「仅本地歌词」「播放服务断开」必须区分，不能统一标成含义不明的「离线」。状态同时包含图标或文字，不只依赖红绿圆点。

轻量成功提示约 3 秒自动消失；需要行动的错误持续到用户处理或关闭，不使用只有悬停才能发现的截断提示。提示不能覆盖进度条或主要操作。

所有产品文案进入现有中英翻译资源。不能用手工拼接固定宽度中文的方式排版，英文变长后需要自然扩展或换行。

## 10. 动效与性能

| 场景 | 时长 | 方式 |
| --- | --- | --- |
| 悬停、按下、颜色切换 | 100–140 ms | 颜色或局部透明度变化 |
| 弹窗与菜单出现 | 160–200 ms | 淡入，可配合不超过 8 的位移 |
| 队列／歌词视图切换 | 180–220 ms | 轻量淡入淡出，避免整页弹跳 |
| 歌词自动跟随 | 220–320 ms | 平缓减速，连续更新时合并到最新目标 |
| 封面切换 | 180–240 ms | 新封面准备好后淡入，尺寸不变 |

默认使用平缓减速，不使用强弹簧回弹。拖动进度条和音量的直接反馈不附加追赶动画；切歌后的大跨度歌词定位可直接到位，避免长距离滑行。

提供「减少动态效果」能力，并在能可靠读取系统偏好时尊重该偏好。开启后关闭装饰运动、缩放和位移，歌词直接定位，保留即时状态反馈。

歌曲列表复用可见项；小封面使用合适的解码尺寸，避免每行处理原始大图。隐藏页面停止装饰动画，整页背景模糊不得随播放位置逐帧重算。不为了视觉效果改变音频或 IPC 更新逻辑。

## 11. 可访问性与键盘操作

按自然阅读顺序组织 Tab 焦点：导航 → 当前页面操作 → 内容列表 → 底部播放控制。弹窗打开时焦点进入弹窗，关闭后恢复；所有操作有清晰焦点环。

- 普通按钮支持 Enter／Space，菜单支持方向键与 Esc，滑块支持方向键调整。
- 焦点位于歌词搜索、歌单名称等文本输入中时，不能被全局播放快捷键抢走空格。
- 播放／暂停按钮的可访问名称随状态变化，当前歌曲、选中歌单和进度值提供对应语义。
- 鼠标悬停才出现的按钮，在键盘进入该行时同样显示；提示文字可以通过聚焦访问。
- 图标与颜色之外提供文字或形状线索，播放中、暂停、选中和聚焦彼此可区分。
- 屏幕阅读器能获取歌名、作者和操作名称；播放时间更新不应持续打断朗读。

## 12. Qt/QML 落地约定

将本规范中的颜色、间距、字号、圆角和动效时长集中到统一主题定义，再由组件引用。颜色表的点分名称是设计 Token，具体 QML 属性名可使用 `colorTextPrimary`、`spaceMd` 等合法名称。主题文件的注册方式按当前资源与构建结构确定。

| 当前文件 | 后续实施职责 |
| --- | --- |
| `frontend/qt-qml/qml/Main.qml` | 窗口、导航、视图切换、全局播放栏、统一主题传递 |
| `frontend/qt-qml/qml/components/QueuePanel.qml` | 队列与歌单布局、曲目行、歌单管理弹窗 |
| `frontend/qt-qml/qml/components/PlayerPanel.qml` | 封面与歌词页面的空间分配 |
| `frontend/qt-qml/qml/components/AlbumArt.qml` | 封面裁切、加载与失败回退、局部环境光 |
| `frontend/qt-qml/qml/components/LyricsPanel.qml` | 歌词状态、来源、搜索与候选选择 |
| `frontend/qt-qml/qml/components/LrcLyrics.qml` | 歌词排版、高亮、跟随与手动滚动 |
| `frontend/qt-qml/qml/components/IconButton.qml`、`TextButton.qml` | 按钮外观、状态、焦点与可访问名称 |
| `frontend/qt-qml/qml/components/SeekSlider.qml`、`PlayerSlider.qml` | 进度与音量反馈，保留已有跳转同步保护 |
| `frontend/qt-qml/i18n/zh.json`、`en.json` | 文案与语言一致性 |

组件接收数据并发出操作信号，继续使用既有 `ipcClient` 边界。UI 设计实施不能把歌词请求、持久化或播放状态管理搬进视觉组件，也不能修改歌单、歌曲和队列的身份语义。

优先顺序：先统一主题与基础控件，再调整队列页和底部播放栏，再处理歌词页与弹窗，最后加入二次元插画和克制的环境效果。已有歌曲封面与本地数据始终保留。

## 13. 交付与验收

后续实现至少提供队列页、歌词页、空状态、编辑弹窗、歌词搜索、失败状态六组真实运行截图；宽窗口使用 1360 × 860，紧凑窗口使用 1000 × 640。截图需注明语言、缩放和状态。设计稿、离屏启动和构建通过均不能替代真实界面验收。

- [ ] 主体呈现深紫灰背景、月光紫交互色和少量樱粉点缀；插画风格一致。
- [ ] 普通文字、歌词、占位提示、焦点环及控件边界满足本规范对比度目标。
- [ ] 在最小窗口、中英文和常见显示缩放下，标题、表单和底栏没有重叠或裁切。
- [ ] 队列／歌单切换、歌曲行单击播放和全部现有播放操作保留。
- [ ] 清空队列、移除歌曲、删除歌单的作用范围明确，不改变本地文件与持久歌单语义。
- [ ] 点击进度条一次生效，拖动不回跳，音量零值显示正确。
- [ ] 歌词换行稳定，手动滚动不被抢回，切歌后没有旧歌词或旧封面串入。
- [ ] 歌词搜索来源与候选步骤保留；没有加入当前版本不支持的 ASR 功能入口。
- [ ] 弹窗提交失败保留输入，键盘焦点恢复正确，错误提供可执行的下一步。
- [ ] 仅使用键盘可以完成导航、播放、歌单操作、歌词搜索与弹窗关闭。
- [ ] 封面缺失、文件不可用、搜索失败和播放服务断开均有可理解的反馈。
- [ ] 减少动态效果后仍能识别播放、加载、聚焦和选中状态。
- [ ] UI 改动通过对应构建、现有测试和实际播放／IPC 验证，并完成真实窗口视觉检查。

本规范首版交付物为文字设计系统。目标插画、主题组件迁移和真实界面截图属于后续实现交付物。
