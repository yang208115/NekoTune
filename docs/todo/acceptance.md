## 独立跟进的边界缺陷

| 涉及功能 | 对应缺陷 | 修复时回归 |
| --- | --- | --- |
| 1.3 Gapless | 9.1 解码取消可能丢失唤醒；9.9 切设备丢预加载及过期事件重播 | 满缓冲取消／退出、输出设备切换、过期边界事件 |
| 1.4 ReplayGain | 分析线程使用同一 `PcmDecoder`，9.1 可能使取消／析构卡死 | 满缓冲时取消分析、退出等待与资源释放 |
| 1.6 Crossfade | 9.2 尾部 0／1 帧故障已实测；另受 9.1、9.9 影响 | 迟到预加载的 0／1／2 帧边界、有限输出、无重复身份切换、取消与设备切换 |

解码取消问题来自本次源码复核：`PcmDecoder::cancel()` 在未持有等待谓词互斥锁时置位并通知，存在检查谓词与进入等待之间丢失通知的窗口；本次未强制复现该线程竞态。

Crossfade 补充探针直接链接当前构建库，生成两首各 100 帧的 48 kHz 双声道 WAV。先调用 `releasePlanWait()`，渲染当前曲的前 99／100 帧，再预加载下一首、授权 1 ms Crossfade，继续渲染：

- 剩 1 帧：输出 `-nan`，探针检测非有限值后退出码 1。
- 剩 0 帧：进程崩溃，退出码 139。
- 探针、源码与截图留在本地 `build/todo-crossfade-probe*`、`build/todo-acceptance-images*`；它们是忽略的本地验证产物，不属于仓库回归用例。

上述边界未通过，相关功能仍按用户确认的日常可用标准放行；后续修复应把该场景加入正式测试。

## 2026-10-25 内存优化

10.4–10.6 已完成；共用解码器中的 9.1 一并修复，从待办清单移除。

| 原项目 | 实现与回归 |
| --- | --- |
| 10.4 播放解码缓冲导致 malloc 碎片 | 解码线程启动前分配固定 PCM 环形缓冲；默认本地 3 MiB、网络 8 MiB，响度分析保留 256 KiB。转换临时区复用；渲染缓冲按实际 lookahead 预留，不再每路固定 reserve 12 MiB。覆盖小环／默认容量的多次回绕、逐样本一致性、容量背压与 50 次取消析构；Gapless／Crossfade／ReplayGain 常规回归通过 |
| 9.1 解码线程取消丢失唤醒 | 在等待谓词的互斥锁下设置取消，再通知；覆盖满缓冲及读取唤醒后立即取消、重复取消与析构 |
| 10.5 壁纸与背景图解码尺寸 | 图片按显示尺寸 × DPR 解码，禁用大图缓存；背景隐藏、被自定义背景替代或清空来源时清空静态图片，关闭壁纸封面背景时卸载整个子树。覆盖缩放、隐藏／显示、来源清空及卸载；普通与 2× 缩放回归通过 |
| 10.6 扩展视图独立 QQmlEngine | 同一宿主及控制器／翻译器中，按扩展与 generation 复用引擎，各视图使用独立上下文。保留主题单例的公共宿主上下文；展示元数据、窗口上下文变化不重建根对象。覆盖同名组件／翻译隔离、共享引擎、独立窗口／壁纸上下文、局部状态、同路径文件修改后的热重载、新旧代次共存及最后引用释放 |
